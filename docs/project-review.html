值得保留

这些不是“没问题所以略过”，而是后续改动不能破坏的基础

薄宿主方向正确

Server 只拥有 HTTP、env、日志和进程生命周期；业务 router/service 在 tRPC 包，DB 通过 Context 注入。 这让 createApp()、createCaller() 和资源关闭都具备可测试入口。

契约值与 UI 文案分开

L | M | H 在 tRPC wire schema 与 DB 中保持语义一致，展示标签留在 Web。 这比数字暗码更适合表单、日志和跨 Agent 沟通。

tRPC v11 接线基本规范

Web 使用 import type { AppRouter }、createTRPCOptionsProxy 和 TanStack Query options factory，没有回退到手写 query key 或旧 hooks 集成。

SuperJSON 两端对称

Server transformer 与 Client terminating link 都配置 SuperJSON，Zod 的 z.date() 因此能在 wire 边界正确恢复和验证。

DB 所有权单一

schema、Drizzle Kit 与 migrations 都归 @workspace/db；运行时由宿主创建 DB， 没有在 tRPC 包中建立进程单例。

Disposable demo 的原则合理

Todo 用于证明纵向链路，不生成需要用户随后删除的 migration。真正产品 schema 稳定后再生成首个 migration， 这比把 demo 历史带进生产更干净。

依据与边界

优先使用仓库安装版本携带的技能与类型声明，不依赖记忆猜测

  • tRPC 本地技能：server-setup、validators、client-setup、 links、react-query-setup；仓库安装版本 11.18.0。 可继续查看 官方 Validators 文档。
  • Drizzle Kit 本地技能 revision 12，并直接核对当前 RC 类型声明。 Migration 选择可查看 Drizzle 官方文档。
  • Node 22 虽支持有限的 TypeScript 类型剥离，但本模板生产运行不依赖该能力。 参考 Node.js TypeScript 文档。
  • 初始评审为只读分析；后续已修复 Server build、Node 22 基线和 tRPC 契约包边界。仓库本来就是脏工作树；报告明确区分修复与已有修改，不把未跟踪的 AGENTS.md、SETUP.md、 packages/api 误称为已经提交。
  • 未要求模板内置 Auth、平台部署、任务队列、完整可观测性或复杂 repository 抽象。 这些应由真实产品需求触发，不应为了“生产级”口号提前堆入模板。
